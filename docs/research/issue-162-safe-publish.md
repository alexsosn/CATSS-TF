# #162 — canonical no-clobber publication and tf-build adoption

Baseline `a432c5353eb90dcce2ad67120b0578dac71f7b1d`, researched 2026-11-17. Scope: **publication correctness and shared infrastructure**, not CATSS semantics, full Libronix feature parity or corpus redistribution.

## Evidence from actual code and filesystem

1. `src/catss_tf/canonical_materializer.py::materialize_corpus` checks `destination.exists()` before reading and compiling. `_publish_bundle` stages a directory next to the output and then calls `temp_path.replace(destination)`. An independent local Linux POSIX probe created an empty destination directory after a staged directory and called `Path.replace`; it succeeded, *changed the destination inode* and replaced the empty directory with the staged file. Any concurrent actor claiming a previously absent empty directory can therefore be silently overwritten. Existing `destination.exists()` also evaluates false for a dangling symlink.
2. `src/catss_tf/agora_adapter.py::_check_inputs` manually checks output is existing real empty host staging, and separately rejects symlinked source, source/output alias and ancestor overlap. The published `tf_build.agora.prepare_agora_output` owns **the exact host-output staging preflight**, while CATSS-specific source/overlap rules must remain here.
3. Verified **published** tf-build GitHub release `v0.1.0rc1` (2026-10-28) has wheel `tf_build-0.1.0rc1-py3-none-any.whl` at `https://github.com/alexsosn/tf-build/releases/download/v0.1.0rc1/tf_build-0.1.0rc1-py3-none-any.whl` with GitHub asset digest `sha256:dff2a14c0299422b4716217d04e6d43b47e714f4dacdb21d9939292051e82c9a`. Main's `0.1.0rc2` is **not** published. The rc1 `tf_build.publication.publish_path_no_clobber` calls Linux `renameat2(..., RENAME_NOREPLACE)`, macOS `renamex_np(RENAME_EXCL)`, or Windows `os.rename`; it raises `FileExistsError` when another path occupies destination and raises on unsupported OS/filesystem rather than silently falling back to a racy check+replace. This satisfies our atomic no-clobber contract. `tf_build.agora.prepare_agora_output` confirms a real, empty, existing output directory, raising `AgoraOutputError(ValueError)`.
4. Pin the **actually published wheel** by explicit direct `tf-build @ HTTPS-wheel#sha256=...` dependency in `pyproject.toml`. Note that published tf-build has a `text-fabric>=13.1,<14` transitive runtime dependency; this makes a previously dependency-light core install bring in TF. Accept that as a deliberate, documented packaging tradeoff for correctness and explicitly verify build/wheel installation. Keep CATSS `[tf]` extra and existing source licensing policies; do not claim new CATSS release or upgrade pinned parent corpora.
5. The actual CATSS native writer's `_write_canonical_tf` and TSV sidecars remain authoritative; tf-build only replaces the final rename operation. On publication failure the existing `except Exception` must remove the staged path, never the claimed destination. Existing Agora adapter hardlink finalization still aborts on a concurrent claim.

## Threat and test boundaries

- Deterministic interleaving at actual writer call: inject another actor's *empty output directory* after initial preflight, assert public `materialize_corpus` raises `FileExistsError`, competitor inode still identical, no native files overwritten, and no abandoned `.<name>.tmp-*` staging dirs. On Linux old `Path.replace` demonstrably violates this.
- Dangling destination symlink must never be silently replaced. Assert link preserved and target not created.
- Instrument Agora preflight to prove `prepare_agora_output` runs **before** parsing/materialization while source-symlink/overlap checks still fail closed.
- Metadata regression for immutable wheel URL and hash, importable published functions; a fresh wheel-install CI test remains necessary to verify PEP 508 installation behavior.
- Real 46-file canonical source→TF reload→Agora CI acceptance verifies no output/provenance regressions. Actual concurrency behavior comes from real filesystems in the synthetic tests, not mocks of the publication function.
